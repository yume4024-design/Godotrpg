# 讀檔場景切換分幀實驗 — 2026-10-30

針對服務測試的讀檔尖峰，試驗在全黑轉場時把舊場景釋放及新場景建立分到不同幀；同時在轉場期間暫停森林標籤更新，避免存取已釋放的節點。原生 Release 測試顯示**沒有足夠證據支持改善，實驗已撤回**。正式讀檔繼續重建場景，沒有啟用同地圖重用；不改 v0.6.1、固定 RC4 或存檔 Schema。

## 可重複測試

Windows、Godot 4.7.2、RTX 3080、Compatibility、1280×720、60 FPS 上限；兩次均在隔離 Windows Release 包執行相同序章及三輪探索、交易、戰鬥、存讀檔，**各169／0**。基線提交 `3f860b26bd26694e16d840def74e305a475f2871`；實驗從 `306150016f1ee5a6b741542894023fc5181abcd6` 建立，兩提交的 runtime 場景、程式及資產相同，測試 probe 雜湊一致。實驗僅以收據所列兩個 runtime overlay 加入分幀和標籤保護。

時間是牆鐘間隔；完整切換包含淡入淡出。各一次短測、每次僅三輪，並非隨機交錯或 GPU 剖析；個別最大值受波動影響，不能推論此方法必然使效能變差。它增加等待，且未顯示穩定改善，所以不保留。

實驗期間另通過圖形回歸：入隊前後讀檔54／0、森林標籤258／0、三區地圖77／0、序章94／0、獨立圖形重啟25／0；撤回後 Godot Check 通過。實驗只測這些範圍，不等於30分鐘長測或人工輸入驗收。

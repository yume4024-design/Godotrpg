## 可操作結果

1. 新遊戲完成教學，與公會長接 Q001，再與莉雅交談；對話完成後加入第二名隊員，原 NPC 隱藏並取消碰撞。
2. 按 M 開啟旅途手冊，使用上方角色選擇切換雷恩／莉雅；狀態、背包、技能、裝備四頁可操作。M／Esc 返回探索，選單期間不移動、不互動、不執行 R 重設。
3. 初始背包提供青銅短劍、柳木法杖與旅人皮衣各一件；劍限雷恩、法杖限莉雅，皮衣可交換使用。裝備會移出背包，替換／卸下返回舊物品；有效數值即時更新。
4. 進森林並走入教學戰區，E004 觸發 B001：雷恩和莉雅對兩隻 Lv1 史萊姆。勝利給 12 金幣、每位隊員 20 EXP，兩人升 Lv2；确认返回後才完成 `battle_b001_won`／`e004_done` 與 Q001 的 OBJ01。
5. 敗北不發獎；重試或撤退還原進戰前 HP／MP／物品數量。撤退後不立即再次觸發同區；走出再走入可重新挑戰。森林演練仍不給主線旗標、金幣或 EXP。

升級規則：累計門檻 `10 × 等級 × (等級 − 1)`，Lv2 為 20、Lv3 為 60、Lv6 為 300，暫定上限 Lv20／3800 EXP。每位已入隊角色獲得全額 EXP；升級增加生命／魔力上限及相應剩餘值，死亡角色維持 HP0。細節见 [GAME_DESIGN](GAME_DESIGN.md)。

## 狀態與交易

- `CombatantState` 保存各角色等級、EXP、HP／MP 和裝備，依唯讀定義計算有效數值；戰鬥與 UI 共用同一實例，不修改 `.tres`。
- `InventoryManager` 保存金幣和物品；`RewardManager` 保存組合獎勵來源帳本，先驗證完整獎勵包，再同步套用金幣、全隊 EXP、物品與帳本，最後通知觀察者。重入及重複來源被拒絕。
- `PartyActions` 驗證可操作狀態、角色、數量、槽位與使用條件，協調背包和角色修改。UI 僅發送請求。
- 正式招募表只有莉雅；三人上限以獨立測試角色驗證，沒有艾琳提早入隊。地圖切換保留隊伍和裝備；探索仍只顯示隊長。
- E008 獎勵包與來源去重只有隔離測試，並未把 E008 整段交付標成可玩。Q001 的 rewards 仍只讀顯示；任務完成、獎勵及旗標整體交易留 P5。

70／82 是同一套 P4 測試的無頭與圖形兩種模式，不能相加稱為 152 個獨立案例。圖形模式以 Godot `Input.parse_input_event` 送入鍵盤／滑鼠事件，經實際 UI、輸入處理和物理迴圈操作；本輪沒有另外執行作業系統層的原生滑鼠驗收。測試會將角色移至起測點、建立敗北用低 HP 狀態，再操作真正的對話、移動、回合和按鈕，並非全程人工通關或時長驗收。

P2 舊測試明確將 EventRunner 限定為 E001/E002 歷史子集，以保留其「未支援事件應拒絕」契約；正式 Main 啟用 E001～E004，P4 測試從正式啟用設定走完主線，沒有用注入旗標替代入隊或 B001 勝利。文件本地連結、PowerShell 工具語法與 Git diff 空白檢查均通過。

邊界已驗證：重複入隊／第四人拒絕、非法／負值／小數獎勵不部分提交、通知中的重入不重發、每人全額 EXP、門檻前一點與精確門檻、一次跨多級、死亡不復活、Lv20 上限、裝備替換不疊舊加值、耗盡／滿血／死亡用藥拒絕、切圖狀態持續、撤退區域抑制、演練不能刷主線獎勵。

# 灰石村碰撞載入修正與 Windows 基準 — 2026-11-08

## 結論

將新版灰石村的1,272個匯入碰撞代理離線轉為實心方盒，共用100種尺寸。實際範圍、節點、局部變換、碰撞層與可行走路線保留。Windows Release短測中，碰撞轉換／掃描中位數7.563→0.980ms，村莊初始化28.558→23.998ms。整幀尖峰仍波動，**未宣稱卡頓全面解決、30分鐘長測或發布通過**。

平台依使用者最新指示永久取消Android／iOS，僅Windows，參見[桌機與畫質規範](WINDOWS_PC_TARGET.md)。角色／場景精緻度提升是後續有效工作；本項沒有以變更碰撞冒稱美術升級。

## 修改

- `assets/collisions/greystone/reference_v5/bounds.tscn`：由既有bounds.glb計算，僅碰撞資料；100個BoxShape3D、1,272個碰撞節點。原GLB保留。
- `scenes/world/greystone_reference_master.tscn`：Bounds改引用離線資產。舊村莊、正式main.tscn、角色與RPG資料不改。
- `scripts/tools/bake_reference_bounds.gd`：可重跑的製作工具，保存來源SHA256及來源數量，使用原本逐面AABB規則。
- `tests/reference_bounds_test.gd`：獨立載入原GLB並用舊方法轉換，逐節點對照，再於兩個獨立物理世界比較射線與玩家膠囊。
- `tools/godot.ps1`：增加BakeReferenceBounds／TestReferenceBounds。
- 效能工具補細分CPU時間及幀區間；修正兩層量測插入的守門比對失敗，兩項Python測試確認插入後去除量測行可還原原始遊戲語句。
- 解析度選項由探針實際設定並回報渲染尺寸；不能只靠啟動參數宣稱1080p，因歷史故事測試會改回1280×720。

`BlenderVillageGeometry`遊戲腳本已恢復原版本。較早以來源Shape metadata重用Box的試作通過17,507項功能測試，但碰撞段中位數8.484ms，沒有改善，已撤回。試作測試移至artifacts/rejected-box-cache-20261108；對應Release證據保留，不納入有效修正。

## 1080p量測工具修正

首次高解析度診斷流程169／0，但包外檢查拒絕結果：ViewportTexture.get_size()回報2880×1620。獨立原生探針證明，在本機Godot 4.7.2的canvas_items／1.5倍UI縮放下，實際get_image()及WebP是1920×1080；不能用該Texture尺寸欄位當作實際渲染像素。工具已改用停止計時後讀回的最終Image尺寸，逐階段另記Window尺寸，不在每幀做GPU畫面讀回。

TestProfileResolution：720p／1080p兩項均通過，UI縮放保留。第一次收集器失敗紀錄保留，不能悄悄改標通過。後續建立 verified 包時程序中斷，沒有匯出成果；確認程序消失後另建 verified-retry 包，保留中斷目錄。

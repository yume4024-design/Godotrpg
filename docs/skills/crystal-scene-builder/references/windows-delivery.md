# Windows 固定包交付

僅在可玩候選匯出屬於本輪授權範圍時使用。Skill 本身不授權推送、發佈外部平台、合併 main、重設工作樹或啟動其他平台；依現有使用者授權執行，不重複索取已給予的許可。

## 固定來源與版本契約

來源場景回歸通過後，檢視變更並記錄提交。共享文件夾雜使用者修改時，只提交本輪內容；保留原始專案與所有舊包。實際打包來源 SHA 與最後報告提交 SHA 分開記錄，不能用較新的文件提交冒稱包內程式版本。

匯出前核對三者一致：

1. `project.godot` 的 candidate／qa feature 版本與入口。
2. `export_presets.cfg` 對應平台、feature 與 preset。
3. 包內 QA 腳本的明確預期版本。

保留正式基準版本檢查。若只把候選改為 RC3、QA 仍寫 RC2，應修正契約並重匯出，不刪掉檢查或直接接受任意版本。

使用適合的乾淨驗證工作樹；已有乾淨且用途相容的工作樹時可重用，否則建立本輪專用工作樹，不把它當第二個正式專案。更新來源後確認 HEAD 與實際內容一致。匯入產生的 `.import`／音訊匯流排正規化須辨識並記錄，不能藉打包回退其他人的改動。

目前 Project Crystal 可用：

```powershell
# 在原專案根目錄執行；變數先指向已確認的來源與全新輸出目錄。
./tools/build_blender_windows.ps1 -SourceRoot $cleanValidationRoot -BuildRoot $newBuildRoot -CandidateFamily Reference
./tools/test_reference_windows.ps1 -BuildRoot $newBuildRoot
```

`Reference` 僅用於新版參考灰石村；礦坑或其他候選先讀工具參數及對應測試，不能拿村莊證據認證另一場景。沿用 `tools/godot.ps1` 已設定的引擎，不擅自升級。

## 建置失敗時

核對退出碼、引擎錯誤及完成 marker；保留原始日誌在 artifacts／builds，提交精簡結果與雜湊。匯出成功只代表產物建立，還不是功能通過。

對已診斷的暫時性匯入／快取問題，可在來源未改變、舊失敗輸出保留的前提下做一次乾淨重試。若再次出現同類錯誤，停止盲目重試並定位依賴或資源問題；不能過濾 ERROR、降低驗證或拿舊 PCK 補成功。來源修改後建立新的提交／輸出證據鏈。

Git 鎖、身份或換行狀態問題按一般專案維護處理，不把某次移除 stale lock 變成每輪固定步驟。不因遇到鎖就刪除、不以全域 reset/clean 修復匯入問題。

## 實際包內測試

測試用 APPDATA／LOCALAPPDATA／暫存及存檔槽隔離。舊檔使用複本，記錄並比對來源雜湊；包內測試不可改寫玩家原檔。

- 啟動原生 Release 執行檔，確認版本、feature、真正圖形顯示與載入完成。
- 走序章、NPC 對話、交易／旅館、戰鬥與跨場景返回；驗證隊伍、金幣／物品、單次獎勵及進度。
- 對本輪新增資產核對包內實際 Mesh、Shader、材質，而非只有資源清單或檔名。特別確認程序材質替代、瀑布與水沫沒有丟失。
- 寫入測試存檔，完全關閉程序後另開程序讀取；驗證舊位置遷移及拒絕無效位置仍保留原檔。不能用同一程序內 request_load 代替重新啟動。
- 另測一般使用者啟動器，不加 smoke／QA 自動離開旗標；觀察窗口回應，再正常關閉，檢查遊戲及啟動器退出狀態。只關閉本輪擁有的程序。
- 查看包內實際畫面，記錄本輪 source tests 與 package tests 的各自結果，保留首次失敗和修正後結果；不能套用舊 RC 的測試認證新包。

自動 InputMap、桌面觸控模擬、短啟動觀察均不等於人工鍵鼠／Xbox、30分鐘長測或 Android 真機驗收。使用者暫停人工驗證時，完成可獨立執行的候選工作並清楚保留該門檻。

## 交付與同步

可攜包採明確檔案清單：exe、pck、啟動器、必要授權、SHA256；依工具產物增補必要依賴。不要整個 candidate 資料夾遞迴壓縮，因普通啟動可能已生成 user_test／日誌。建立 ZIP 後檢查內容、CRC、大小與 SHA256；不把匯出包或使用者資料提交到原始碼庫。

報告至少保存：

- 場景來源與包來源 SHA、引擎版本、候選版本、可重現命令。
- 各測試類別的實際結果、時長、顯示模式、失敗／修正說明、未驗證項目。
- blend、模組 GLB、Godot 入口、原生畫面、建置收據及必要雜湊。
- 正確可用的本機啟動器／ZIP 路徑；區分資料夾層級，保留舊包指南的歷史意義。

更新 TASKS、CHANGELOG、場景報告與指南。已授權 Git 同步時先 fetch，確認祖先關係／快進，再推既有功能分支並查遠端 SHA；不強推或合併 main。混合文件按內容選擇性暫存，核對無關差異仍保留。

本輪驗證工作樹無需保留時，先確保需要的產物已在工作樹外保存，再用管理工具封存。若 App 將它視為主工作目錄而拒絕封存，保留並記錄，不改用手動刪除繞過限制。
